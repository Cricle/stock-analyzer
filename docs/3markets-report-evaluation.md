## 优化措施回顾

### 数据管道优化 (已实施)

1. **ParallelExecutor** — 并行数据获取，每种数据类型独立超时控制
   - Quote/Fundamentals/Candles: 15s 超时 (原 8s)
   - News: 25s 超时
   - 最大重试 2 次，指数退避 (1s, 2s)
2. **DataCacheLayer** — LRU 内存缓存，TTL 300s，最大 1000 条目
3. **DataValidator** — 数据质量评分 (0-100)，基于 5 个基本面字段
4. **ConfidenceCalibration** — 基于数据完整度、信号一致性、历史准确度校准信心值

### LLM 推理优化 (已实施)

1. **DecisionFramework prompt** — 数据完整度 < 60% 时强制 Hold，>= 60% 时必须给出方向性判断
2. **决策矩阵** — 技术面 + 基本面 + 新闻/情绪三维度交叉判断

## 下一步改进建议

### 短期 (1-2 天)

1. **修复基本面数据获取** — 这是信心值无法突破 60 分的根本原因
   - 检查 akshare-rs 的基本面数据接口是否正确调用
   - 增加基本面数据的超时时间 (当前 15s 可能不够)
   - 添加基本面数据的降级策略 (使用缓存数据或默认值)

2. **优化 LLM 调用** — 解决 PLTR 卡住问题
   - 为 Research Manager Decision 阶段添加超时机制
   - 考虑使用更快的模型做初步筛选，只在关键决策时使用 mimo-v2.5-pro

3. **增加新闻和情绪数据** — 当前新闻数据可能不完整
   - 检查 akshare-rs 的新闻接口
   - 添加新闻数据的质量评分

### 中期 (3-5 天)

1. **决策框架优化** — 当 60% 阈值无法达到时，考虑降级策略
   - 如果基本面数据缺失，但技术面信号强烈，可以给出有条件的 Buy/Sell
   - 添加 "数据不完整时的保守策略" prompt

2. **数据源多样化** — 不依赖单一数据源
   - 添加备用数据源 (如 Yahoo Finance, 东方财富等)
   - 实现数据源自动切换机制

3. **LLM 推理链优化** — 减少 LLM 调用次数
   - 合并 Research Manager Decision 和 Portfolio Manager Decision
   - 使用结构化输出减少解析时间
